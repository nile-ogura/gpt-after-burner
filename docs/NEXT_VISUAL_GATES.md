1. All three implementers report **SOURCE HOLD** before the capture starts. Record source revision/file hashes or an equivalent source snapshot. No geometry, material, shader, exposure or QA-tool edits during the run. If a fix is made, start a separately identified run.
2. Use the same browser/runtime and renderer between paired shots. Desktop is 1440×900, portrait is 390×844, device scale factor 1. High is actual renderer/composer pixel ratio 1.00, shadows/bloom enabled. The controlled balanced diagnostic is ratio 0.65, shadows/bloom disabled; this differs from the ordinary 0.75 balanced menu setting. 3. Use a fresh launch/reset with the same game seed (`0x41465452` is the current default), difficulty `standard`, STAGE 1 and recorded simulation/presentation times. Clean aircraft/environment shots have no residual projectiles, smoke, explosion, damage wash or camera shake. Pause simulation and freeze presentation time for static pairs. `freezePresentation` alone does **not** pause simulation. Record the state rather than treating an elapsed wall-clock wait as a fixed game state.
4. Keep player position, bank/pitch/roll, throttle, camera position/quaternion/FOV, world-tile transforms, sunlight/exposure/grade and presentation/environment phase identical within each high/balanced or clean/hit pair, except the intentional effect change. Log those values. Use completed render-frame settling and asset/material readiness, not just an 800ms sleep; the software renderer is much slower than that in some scenes. Project HUD markers using the final camera matrix for the rendered frame.
5. Wait for all cloud and rock maps and the one-time cloud reflection to be ready. Record ready/fallback status, finite geometry/opacity, actual detailed enemy LOD, shader/browser errors, draw calls and triangles. A missing texture, a substituted fallback or failed material compile is an invalid candidate capture, not a successful art comparison.
6. Preserve both unmodified gameplay images with HUD and dedicated detail images with HUD hidden. Detail-camera images are QA views, sometimes outside the playable rail, and cannot replace ordinary gameplay evidence. No screenshot retouching, selective exposure changes or concealment of defects.

Exact old-run camera/time metadata was not saved for every historical normal frame.
