# Quality goals and integration contract

Original Three.js arcade aerial combat experience. Rear chase camera is the default; the user's explicit rear-view requirement takes precedence over the word FPS. Do not claim parity with a commercial AAA release.

Current user condition: low FPS is acceptable on this PC because its GPU is weak. Minimum FPS and hardware60fps are not adoption blockers. Preserve measured results without treating the old smooth-play threshold as a current requirement; visual and functional defects remain independent gates.

## Goals

1. Aircraft: recognizable, carefully proportioned twin-engine swept-wing fighter; PBR surfaces, cockpit, engine interiors, panel detail, moving control surfaces, restrained effects. Strict independent image review.
2. Environment: cinematic ocean, layered atmospheric mountain coastline, clouds, directional sunlight and haze; no placeholder cubes, flat empty horizon, visible seams or excessive bloom. Strict independent image review.
3. Flight and combat: frame-rate-independent controls, banking and acceleration, clear lock/fire/impact loop, threatening but escapable missiles, limited missiles and unlimited gun, original-style 23 numbered stages with video-verified supply/landing/canyon phases, three aircraft, stage HIT and weighted total HIT, reliable restart/pause. Optional modern flares are off by default. No XP or upgrade leveling. Separate functional and image review.
4. Presentation: beautiful, coherent 16:9 full-screen composition, legible restrained HUD, radar, target cues, briefing and debrief, settings and keyboard help, responsive small screens. Independent review at desktop and small size.
5. Validation: production build, meaningful simulation tests, actual browser flight/weapon/restart checks, zero uncaught runtime/shader errors. Preserve review failures and fixes in docs/REVIEW.md.

## Shared module contracts

`src/aircraft.js`: export `createAircraft({enemy=false}={})` -> THREE.Group, points down local -Z, top +Y, span approx 18m, length 18m. `updateAircraft(group, dt, {time, throttle, bank, pitch})` if needed. No scene/camera controls. root integrates.

`src/gameplay.js`: export `FlightGame` class. Pure JS/no THREE required. `new FlightGame({onEvent,seed,difficulty,stageDuration})`; `reset()`; `start()`; `update(dt,input)`; `setPaused(bool)`; `fireMissile()`; `fireGun()`; `deployFlares()`; `cycleTarget()`. Expose `state`, `player`, `enemies`, `projectiles` and optional `tanker`. Player remains near origin as world flies past; player has `{x,y,z,bank,pitch,speed,throttle}`; world forward is -Z; altitude starts 230. Enemies/projectiles plain `{id,x,y,z,...}`. Stable ids. State `hit` is stage kills, `totalHit` weighted total, `lives` includes the active aircraft. `stageKind` is flight/resupply/canyon/landing/return. `landingProgress` and `resupplyProgress` drive visuals. root owns input, camera, rendering and UI.

Landing contact: carrier flight deck world top is 20m, final return simulated altitude is 22m; airport runway top is 80m and service altitude is 82m. The rendered deployed-gear aircraft adds 0.18m to either simulation altitude, matching its −2.18m wheel minimum. These heights must be verified using transformed geometry bounds, not a box center alone.

Manual arcade roll: input `rollLeft`/`rollRight`, public `startRoll(+1|-1)`, `player.rollAngle`, and state `rolling`/`rollProgress`/`rollDirection`/`rollCooldown`. Add the angle to aircraft bank and chase-camera roll. It costs no resources and grants no invulnerability; reloading and scripted service/return block it. The exact original stick gesture is not emulated. All 22 simulation tests pass, and paused roll poses passed independent visual review; this does not establish smooth-motion performance. See [ARCADE_ROLL.md](ARCADE_ROLL.md).

Do not modify modules assigned to another implementer. Goals are scoped per agent; if create_goal reports an active shared goal, record scoped goal here/report it rather than replacing the root goal. Reviewers must never label the build AAA solely to close a goal.
