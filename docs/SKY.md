# Cirrus sampling candidate — 2026-10-02

The root implementation moves faint high cirrus from five runtime fragment-noise octaves to a native 256×256 periodic RGBA texture generated once on the CPU. The sky keeps the original sphere, atmospheric gradient, warm horizon/sun, world-direction coordinates, time drift and 8% maximum cirrus blend. Adopted cloud photographs and their fixed world transforms remain separate. This is a rendering-cost candidate, not a new volumetric cloud system.

`src/sky.js` owns sky construction. `src/environment.js` imports it and disposes its texture with the other environment resources. The texture uses linear data color space, repeat wrapping, linear magnification and generated trilinear mipmaps. There is one fragment texture sample and no fragment noise loop. Generation is native code; no official or remote image becomes a game texture.

Read-only Node audit: all byte values finite; grayscale range 0–213; mean opposite-edge neighbor difference 1.365 levels, ordinary horizontal-neighbor difference 2.503 levels. The sampling field is periodic, but these are distinct adjacent pixel centers rather than duplicated equal edge pixels. This does not itself establish absence of visible repetition or banding in the rendered sky.

The build passed, and four completed browser frames passed independent static adoption review: horizon/cloud/player integration in high/.65, a bank view and an above-horizon view. No black/missing sky, conspicuous checker seam, banding, hard horizon ring or cloud fringe regression was visible. Texture metadata and finite geometry are supporting technical evidence, not visual certification by themselves. The first combined run then lost its browser context before performance; its cause is unestablished and its failure is preserved in `artifacts/review-round10/sky-attempt1`. A separate browser completed the source-held performance measurement at high 1.20fps / .65 3.21fps, errors empty, with camera/clock snapshots. No speedup is established.
